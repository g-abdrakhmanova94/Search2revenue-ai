# Сравнение способов поиска

Эксперимент на снимке каталога Softline. Для всех вариантов использовали одну выборку из 914 товарных семейств, по одному SKU на семейство. Основная часть выбрана по хешу, эталонные семейства исходных запросов добавлены, если их не было в выборке.

В тесте 10 запросов из задания и 12 формулировок без названия продукта. Для первых эталон взят из Excel Softline. Для вторых использована предварительная разметка по названию семейства с исключением части сертификатов поддержки, обновлений и допмодулей. Запрос о хранилище паролей прошёл через все способы, но его качество и место в рейтинге не оценивались, поскольку среди этих 914 семейств не нашлось размеченного кандидата.

## Как устроены варианты

| Код | Что запускали |
|---|---|
| S1 | multilingual E5-small INT8, сортировка по косинусному сходству |
| S2 | SQLite FTS5 и BM25 по полям карточки |
| S3 | Одинаковые веса BM25 и E5-small после нормализации оценок |
| S4 | Объединение списков BM25 и E5-small по Reciprocal Rank Fusion, коэффициент 60 |
| S5 | E5-small с ранжированием первых 12 кандидатов через multilingual MiniLMv2 |
| S6 | Взвешенный гибрид S3 с тем же ранжированием первых 12 кандидатов |
| S7 | Более крупный multilingual E5-base INT8 с тем же ранжированием |
| S8 | Qwen2.5-0.5B-Instruct INT8 генерирует две переформулировки. Результаты E5-small для исходного запроса и переформулировок объединяются по RRF |
| S9 | S8 с ранжированием первых 12 кандидатов по исходному запросу |

Для сравнения алгоритм стенда запустили на копии той же выборки. Он, как и S2, ищет кандидатов через SQLite FTS5 и BM25. Дополнительно он нормализует термины, распознаёт точный артикул, учитывает роль товара и применяет правила лицензирования. Опечатки он находит, но исправление к запросу применяет только после одобрения менеджером: без одобрения запрос остаётся без результатов. Итоговые допродажи и совместимость проверяли отдельно. Место в таблице отражает совпадение по семейству. Пригодность конкретной лицензии проверяется на уровне SKU.

Qwen получал две разные инструкции и до 16 новых токенов на каждый вызов. Исходный запрос сохранялся в поиске, совпавшие с ним переформулировки отбрасывались. Ранжировщик оценивает соответствие пары «запрос — карточка». Для подтверждения ОС, диапазона устройств и типа покупки нужны поля каталога или документация вендора.

## Как читать замеры

Топ‑4 — число запросов, для которых среди первых четырёх результатов есть размеченное семейство. MRR@4 — среднее обратное место первого совпадения среди 21 запроса с эталоном. При отсутствии совпадения среди первых четырёх вклад равен нулю.

Замеры выполнены на CPU AMD Ryzen 7 3700U. Для составных способов время запроса — сумма замеров отдельных шагов после прогрева, без загрузки моделей и построения индекса. Медиана и p95 считаются по 22 запросам. RAM — максимальный RSS самого тяжёлого из отдельных процессов, включая подготовку индекса, если она выполнялась в этом же процессе. Одновременное размещение всех моделей одного способа может потребовать больше памяти.

Реранкер multilingual MiniLMv2 использовался во всех четырёх вариантах с перепроверкой. Предварительный прогон более тяжёлого BGE reranker v2 m3 остановили из-за времени обработки на CPU.

Веса и токенизаторы загружались в локальное окружение. Зарегистрированные ревизии — [E5-small](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78), [E5-base](https://huggingface.co/Xenova/multilingual-e5-base/tree/1ec9243030a27d1a115d5c340572074c125b58b2), [MiniLMv2 AVX2](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1/tree/1427fd652930e4ba29e8149678df786c240d8825) и [Qwen](https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct/tree/22942cb7d7ba4cc81bb4673549ca4d4614469b5e).

Для запроса про офисный пакет S1 поставил Microsoft 365 первым. S6 поставил его вторым после Visual Studio. При запросе о рабочих станциях ни один вариант не нашёл размеченное семейство удалённого доступа в топ-4.
